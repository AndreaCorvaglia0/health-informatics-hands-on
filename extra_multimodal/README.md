# Extra module: multimodal fusion

An optional module, separate from the course. It is for the students who have finished the project, the
nodules (notebook 04) and want one more topic: models that use an image **and** clinical data together.

| File | What it is |
|---|---|
| `multimodal_fusion.ipynb` | the notebook, 10 steps, about 2 hours, CPU is enough |
| `handbook.pdf` | the theory you need for the notebook, in the same order, with a chapter on embeddings |
| `solutions/multimodal_fusion.ipynb` | the notebook completed (teachers) |
| `solutions/embedding_comparison.py` | a script that compares embeddings (teachers), see below |

It runs on Kaggle like the other notebooks, with the same dataset (`luna16-lung-slices`, folder `nodules`).
Internet must be on: STEP 8 downloads a pretrained network.

## What is inside

One nodule per patient (600 patients, 420 for training and 180 for testing). The masks are the outlines drawn by the LIDC-IDRI radiologists. The question: does a model that sees both the image and the clinical
data predict "alive after one year" better than a model that sees only one?

| Step | Topic |
|---|---|
| 1-3 | the patients, the clinical table, training and test patients |
| 4 | a model on the clinical data only |
| 5 | measurements from the mask (the idea of radiomics) and a model on them |
| 6-7 | early fusion and late fusion |
| 8 | embeddings from a pretrained network |
| 9 | intermediate fusion: a small network with two branches |
| 10 | compare the models, then see how the data were generated |

**The clinical data and the survival are invented.** The images are real. Age, smoking history, performance
status and the outcome are generated by a formula inside the notebook, with a fixed seed. Nothing in this
module has a medical meaning: it teaches the method.

## Results of the solution (test AUC, one split, CPU, about one minute)

| Model | AUC |
|---|---|
| clinical data only | 0.76 |
| image measurements only | 0.74 |
| early fusion | 0.87 |
| late fusion | 0.86 |
| embeddings only | 0.62 |
| early fusion with embeddings | 0.79 |
| intermediate fusion | 0.74 |

The two single sources are about equal (0.76 and 0.74: the difference is noise). Early and late fusion are clearly
better than both, and equal to each other. The embeddings of the whole patch are the weakest source. The
intermediate fusion network is no better than a single source and well below early fusion: 420 training patients
are too few to learn the image branch from scratch. The notebook says so. It is a useful result to discuss. With
180 test patients, differences of 0.02 or 0.03 are noise.

## Two more challenges on embeddings

At the end of the notebook, "If you have finished" has two new challenges. Challenge 4 cuts a 32 x 32 crop around
the nodule and computes the embeddings on the crop. Challenge 5 uses another network, DINOv2, on the whole patch
and on the crop. The solution notebook runs both (it installs `transformers`). The handbook, chapter 5, explains
what is compared.

| Embedding | AUC alone | AUC with clinical data |
|---|---|---|
| DenseNet121, whole patch | 0.62 | 0.79 |
| DenseNet121, crop | 0.78 | 0.87 |
| DINOv2, whole patch | 0.57 | 0.75 |
| DINOv2, crop | 0.67 | 0.81 |

Telling the network where to look (the crop) is the big effect, far larger than the noise. With the crop, DenseNet121
does as well as the five measurements. DINOv2 is below DenseNet121 in every row.

The script `solutions/embedding_comparison.py` gives the same numbers outside the notebook, with the R2 for the
diameter and a DINOv2 variant (mean of the patches). Run it with
`python embedding_comparison.py /path/to/luna16-lung-slices`. It needs `monai` and `transformers`.
